# 与利用相关的静态信号

只有当任务要求评估可利用性或安全影响时，才使用这份参考。要陈述"有证据支持的原始能力（primitive）"以及"额外的运行时条件"。永远不要把"没有看到某个静态产物"当作"不存在"的证明。

| 观察到的证据 | 安全相关含义 |
| --- | --- |
| Libc 版本/构建 | 收窄偏移、gadget 集合、堆实现以及已知的加固行为；条件允许时在运行时确认实际映射的 libc。 |
| seccomp 过滤或策略证据 | 可能限制可用的系统调用；允许/阻断哪些系统调用必须从过滤器或实际观察到的行为推导，而不能只凭"存在过滤"这一事实。 |
| `GNU_STACK RWE` | 请求了可执行栈；shellcode 是否可行仍取决于运行时是否强制、输入放置位置以及控制流原语。 |
| `GNU_STACK` 缺失 | 栈是否可执行未知，取决于 ABI/内核策略。 |
| 运行时证据确认 NX 已关闭 | shellcode 更可行，但仍需要能把执行重定向到攻击者可控内存的手段。 |
| 非 PIE + 部分 RELRO | 固定 ELF 基址加可写 GOT，使 GOT 覆写成为更强的候选，前提是存在写原语且布局允许。 |
| 已确认 PIE | 利用通常需要 ELF 基址泄漏，或用其他方式桥接到已知绝对地址。 |
| Full RELRO 证据 | 重定位后 GOT 预期只读；去找别的目标，别假设还能覆写 GOT。 |
| 静态链接 | 常规外部 libc 不会单独映射；使用内嵌的 libc/符号，并以不同方式评估 GOT/PLT。 |
| 已 strip | 具名逻辑与边界缺失，需要从动态符号、字符串、代码和交叉引用重建。 |
| 观察到 canary 插桩 | 被选中的代码带 canary 检查；覆盖面必须逐函数核实。 |
| 未观察到 canary 产物 | canary 状态未确定，尤其在 stripped/static/内联代码中；在声称存在栈溢出路径前，先检查相关的写路径。 |
| 已证明某个可达函数没有 canary | 如果攻击者可控的溢出能到达那一帧，则栈溢出、返回地址覆写或栈迁移可能可行。 |
